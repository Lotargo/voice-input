# Ручные релизы Voice Input

Репозиторий: `Lotargo/voice-input`, публичные исходники и GitHub Releases. GitHub Actions отсутствует. Для скачивания и проверки обновлений пользователю не нужен токен.

## Версия и публикация

1. Установите новую стабильную версию: `scripts/set-version.ps1 -Version 0.2.1`. Скрипт меняет Cargo.toml и синхронизирует Cargo.lock. Tauri наследует версию Cargo; дублировать её в tauri.conf.json не нужно.
2. Добавьте `releases/0.2.1.md` с описанием изменений и ссылками на два варианта. Раздел `## Что нового` попадает в манифест для приложения. Patch — исправления, minor — новые возможности, major — несовместимые изменения. Номер опубликованного релиза не используется повторно.
3. Выполните `cargo fmt --check`, `cargo test --locked` в `src-tauri/`, `node --test scripts/test-ui.cjs` в корне и проверки изменённого поведения. Закоммитьте исходники и описание релиза.
4. В корне выполните `scripts/build-windows.ps1 -SkipPrepare`. Пакеты разделены по типу и версии; подпись NSIS создаёт Tauri, подпись portable ZIP — signer той же CLI. Обе подписи включают версию в защищённый комментарий.
5. Проверьте пакеты. Выполните `scripts/publish-release.ps1`. Нужны GitHub CLI и авторизация владельца с правами на репозиторий. Скрипт проверит чистоту исходников, коммит сборки и SHA-256, отправит main и тег, создаст черновик, загрузит все файлы и только затем опубликует релиз как Latest. `-Draft` оставляет его черновиком.
6. Откройте публичный релиз и оба JSON-манифеста без GitHub-авторизации. Проверьте кнопку обновления в portable и установленной копии. Не переписывайте опубликованный тег или артефакты: выпустите следующий patch.

`-OutputDirectory` у обоих скриптов задаёт одинаковый альтернативный корень dist. Сборка должна соответствовать текущему коммиту: изменение исходников после упаковки требует повторной сборки.

## Состав релиза

- `Voice-Input-Portable-windows-x64.zip` и `.zip.sig` — папка `Voice-Input/`, EXE, четыре DLL, модель, `portable.json`.
- `Voice-Input-Setup-windows-x64.exe` и `.exe.sig` — NSIS.
- `latest.json` — версия, описание, дата UTC, платформа `windows-x86_64`, HTTPS-ссылка и подпись NSIS.
- `latest-portable.json` — то же для ZIP. Форматы намеренно разделены: portable остаётся portable.
- `SHA256SUMS.txt` — контрольные суммы обоих пакетов, подписей и манифестов.

Имена файлов стабильные, номер содержится в теге и локальной папке. Кнопки скачивания используют `/releases/latest/download/...`, манифесты указывают точный тег `/releases/download/vX.Y.Z/...`.

## Ключ подписи

Рабочий ключ находится **вне репозитория**: `%LOCALAPPDATA%\VoiceInput\release-signing\update.key`. Каталог доступен текущему Windows-пользователю. Ключ защищён случайным паролем, а `password.dpapi` хранит пароль в зашифрованном Windows DPAPI виде для этого пользователя. Скрипт сборки передаёт расшифрованный пароль через окружение дочернего процесса и затем восстанавливает окружение. В репозитории и приложении находится только публичный ключ.

`scripts/initialize-signing.ps1` создаёт ключ только для первоначальной настройки. Если публичный ключ уже настроен, скрипт запрещает автоматически генерировать другой взамен отсутствующего приватного. Существующие пользователи доверяют первоначальному ключу. Его потеря не исправляется новой парой без отдельного перехода для клиентов.

Сохраните закрытую резервную копию ключа и возможность восстановить пароль в защищённом хранилище. Копия `password.dpapi` сама по себе не переносится на другой Windows-профиль или компьютер. Приватный ключ, пароль и их резервные копии нельзя добавлять в Git или релиз. Скрипт не выгружает их в GitHub. Для независимых сборок используйте собственный идентификатор/репозиторий/ключ; они не должны подменять официальный канал обновлений.

## Ограничения

Диктовка и транскрипции остаются локальными. HTTPS используется только после явного нажатия проверки/установки. Отсутствует фоновая загрузка. Установка блокируется во время диктовки; на время загрузки/замены запуск записи также заблокирован, включая глобальную горячую клавишу.

Перед обновлением приложение предупреждает о потере записей из RAM. Portable готовит и проверяет пакет до выхода, ждёт завершения конкретного родительского процесса и сохраняет резервные копии заменяемых файлов. Ошибка копирования приводит к откату и попытке запуска прежней версии. При аварийном отключении питания автоматическое восстановление не гарантируется; резервная копия остаётся в `updates/update-*/backup/`. Приложение не удаляет эти копии автоматически. Очистить старые копии можно после проверки успешного запуска новой версии.

Подпись обновления проверяет происхождение и версию пакета, но не заменяет Authenticode. Windows SmartScreen может показывать предупреждение. Установщик/portable требуют Windows 10/11 x64; более высокие права сторонних редакторов всё ещё могут блокировать диктовку.

Официальная спецификация механизма установленной версии: [Tauri Updater](https://v2.tauri.app/plugin/updater/). Portable использует его загрузку и проверку подписи, затем собственную замену файлов.
