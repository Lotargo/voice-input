# Освобождение моделей и CLI: проверка 2026-11-15

Отчёт фиксирует исходную QA-проверку до подготовки релиза 0.4.3. Упоминания локальной версии 0.4.2 и отсутствия публикации относятся к этому этапу. Новая функциональность выпускается как 0.4.3; см. [заметки релиза](../../releases/0.4.3.md).

## Цель и требования

Проверить освобождение весов Vosk, GigaAM и Nemotron; сделать настоящий выход ожидающим завершения нативного распознавания; добавить локальный CLI для интеграций и проверки приложения. Сохранить существующие правила доставки финального текста, FIFO аудио/команд, пользовательского управления микрофоном и RAM-хранения записей.

## Результат реализации

- Рабочий поток диктовки сохраняется как JoinHandle. `stop_and_wait` сериализован с запуском, устанавливает stop и присоединяет поток без удержания mutex состояния записи.
- После возврата `record_session` уже уничтожены capture stream, pipeline, decoder worker, распознаватель и модель. `stop` в CLI подтверждает завершение только после join.
- `ExitRequested` и `Exit` вызывают идемпотентный shutdown. Новые сеансы блокируются; монитор доставки останавливается и финальные фрагменты при shutdown не отправляются во внешнее поле.
- Асинхронная ошибка запуска сохраняется в `status.recording.message`.
- `voice-input-cli` использует локальный named pipe и общие команды приложения. Нет сетевого сервера, автоматических повторов или автоматического запуска приложения.
- Крестик по-прежнему скрывает окно в трей. Это не завершение процесса; обычная диктовка при скрытии продолжается.

## Реальные модели, синтетическое аудио

Измерение Windows `K32GetProcessMemoryInfo`, поле `PrivateUsage`, в отдельном тестовом процессе. По три цикла создания модели, обработки 1600 синтетических нулевых отсчётов, завершения и уничтожения. Это private committed bytes процесса, не размер файлов модели и не Working Set. Измерение `loaded` сделано до обработки аудио; это не пиковое потребление инференса.


## Проверки

- `cargo fmt --check`, `git diff --check`: успешно.
- `cargo test --locked`: 67 unit + 2 native integration, ошибок нет. Дополнительный native memory QA по умолчанию ignored, выполнен отдельно и прошёл.
- `node --test scripts/test-ui.cjs`: 57/57.
- Regression: уничтожение decoder присоединяет его поток и освобождает принадлежащий ему тестовый объект модели ровно один раз, даже с очередью PCM; stop ждёт освобождения worker и повторный shutdown допустим.
- CLI без запущенного приложения: JSON-ошибка подключения, код 1.
- На отдельном запущенном debug-приложении: `status`, `models`, `records`, `new-record`, `clear-record`, `stop`, `hide`, `show` прошли. Неизвестная команда возвращает JSON-ошибку.
- `start` с текущей GigaAM, затем немедленный `quit` во время запуска: ответ `model_released=true`; процесс завершился. Время quit: 1353 мс. Это проверка выхода во время загрузки, без ожидания захвата живой речи.

Локальные необязательные сырые логи: `dist/model-memory-qa.log`, `dist/cli-cargo-tests.log`, `dist/cli-app-out.log`, `dist/cli-app-err.log`. Они игнорируются Git. В stderr после выхода WebView2 сообщил Failed to unregister class / Error 1412; процесс приложения всё равно завершился.

## Границы проверки

Длительная запись с физического микрофона и полный ручной smoke-набор внешних редакторов в этой задаче не выполнялись. Девять циклов освобождения проверены на синтетическом аудио. Нативная загрузка/инференс не имеют принудительного прерывания: shutdown ждёт их возврата, а зависший native вызов может задержать выход. Ответ CLI quit подтверждает освобождение модели до запроса завершения процесса; исчезновение PID дополнительно проверялось вызывающей стороной.

Руководство и ограничения первого portable-перехода: [CLI](../cli.md). Публикация не выполнялась.
