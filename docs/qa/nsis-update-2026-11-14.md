# Проверка обновления установленной версии через NSIS

Дата: 2026-11-14. Результат: **PASS**.

## Цель и условия

Проверить цепочку из приложения: получение релиза с GitHub → загрузка и проверка подписи → запуск NSIS → замена установленной версии → автоматический перезапуск.

Использованы Windows x64, настройка NSIS `currentUser` и отдельная папка `Installed Voice Input` с пробелами в пути. До начала проверки зарегистрированной установки Voice Input не было.

Исходная тестовая версия **0.1.99** собрана из коммита `84d40b9562c4c5072c7178ef6c30137e0af52d9a`: в отдельной копии исходников изменён номер пакета Cargo и синхронизирован lockfile. Используется тот же код обновления, что в 0.2.0. Генерация подписи для исходного тестового установщика отключена; проверка подписей загружаемых обновлений остаётся включённой.

Целевая версия — настоящий опубликованный [релиз v0.2.0](https://github.com/Lotargo/voice-input/releases/tag/v0.2.0), загруженный самим приложением. Тестовый номер 0.1.99 нужен для проверки доступного обновления при неизменном публичном канале. Он не является ранее опубликованным релизом. Переход со старой 0.1 без механизма обновлений по-прежнему выполняется вручную.

Контрольные суммы:

## Воспроизведение

1. Проверить установленные копии и запущенные процессы. Сохранить настройки, относящиеся к приложению регистрационные записи и состояние его ярлыков.
2. В отдельной копии исходников собрать установщик с меньшей версией Cargo, сохранив публичный ключ, `requireSignedVersion` и настоящий endpoint релизов. Проверить номер версии в готовом EXE.
3. Установить baseline в отдельную папку через `/P /NS /D=<папка>`. Последний параметр NSIS содержит полный путь, включая пробелы.
4. Запустить установленное приложение, открыть «Параметры → Обновления», проверить исходную версию и нажать проверку. Включить журнал процессов и регистрационных версий.
5. Нажать «Обновить и перезапустить». Зафиксировать завершение старого PID, параметры и код выхода NSIS, новый PID, его родителя, путь и версию.
6. Сверить скачанный установщик с релизом, извлечь из него EXE и ресурсы, сравнить их с установленными файлами. Проверить Vosk через `VOICE_INPUT_SMOKE_ROOT=<папка установки>/resources` и `cargo test --locked --test vosk_runtime`.
7. В автоматически открывшейся копии проверить тип установки, параметры и повторную проверку обновлений.
8. Удалить тестовую установку с сохранением данных приложения, восстановить исходные регистрационные записи и проверить отсутствие изменений настроек/ярлыков. Не удалять общую папку данных portable и установленной копии.

В каталоге QA также оставлены тестовый установщик, исходники и вспомогательный деинсталлятор после удаления приложения. Эти файлы не входят в пользовательские сборки.

Изменений продуктового кода и переиздания 0.2.0 для проверки не потребовалось. Служебный `target/release/voice-input.exe` после сборки baseline восстановлен из исходной portable 0.2.0. Публичные артефакты и тег 0.2.0 сохранены.

Этот прогон подтверждает успешный путь обновления `currentUser`, используемый релизом 0.2.0. Отмена установки, нехватка места, аварийное отключение питания и установка с повышением прав в него не входят. Запись с физического микрофона не выполнялась; Vosk проверен на тестовом PCM.
