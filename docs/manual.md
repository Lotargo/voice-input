# Подробное руководство Voice Input

**Локальный голосовой ввод на русском языке для Windows 10/11.** Диктуйте текст в браузере, редакторе или чате, исправляйте распознавание при необходимости и отправляйте сообщения самостоятельно.

Voice Input работает на **Tauri 2 + Rust** и распознаёт речь локально на CPU. В комплект входит **Vosk Small RU**, а **GigaAM v3 E2E** и **Nemotron 3.5 ASR** можно загрузить вручную из каталога. Для диктовки не нужны VPN, API-ключи, облачный сервер или видеокарта.

> **Текущий релиз — [v0.4.3](https://github.com/Lotargo/voice-input/releases/tag/v0.4.3).** Совместимость с конкретными редакторами требует ручной проверки. [CLI и освобождение моделей](cli.md). Первый переход со старой portable-версии на 0.4.3 требует ручной распаковки ZIP.

## Возможности

- **Компактное окно:** размер по умолчанию 480 × 480; вкладки «Диктовка», «Модель», «Параметры» и «Очередь». На главном экране текст текущей записи можно прокручивать без открытия редактора. Новые фразы автоматически видны внизу; ручная прокрутка вверх удерживает место чтения до возвращения вниз. Редактор открывается по кнопке.
- **Живая волна:** в ожидании плавно движется с небольшим размахом; громкость усиливает движение, частоты меняют рисунок. Высокий уровень выделяется янтарным, близость к перегрузке — коралловым цветом и подписью «Слишком громко». Данные поступают из того же локального захвата, что и распознавание.
- **Оффлайн-распознавание:** Vosk Small RU, GigaAM v3 E2E и Nemotron 3.5 ASR.
- **Каталог моделей:** размер файлов и краткое описание, ручная загрузка с паузой, отменой и продолжением после обрыва или закрытия приложения. Скачанные модели можно удалить или назначить основными.
- **Настройки звука:** выбор микрофона, сохранение устройства, обработка отключения и отдельная проверка уровня до 20 секунд без распознавания и вставки текста.
- **Локальное шумоподавление:** отключаемые RNNoise и фильтр низкого гула для постоянного шума, например вентилятора. Работают на CPU; по умолчанию выключены.
- **Транскрипция:** Vosk и Nemotron показывают предварительный текст во время речи; GigaAM выдаёт текст после завершения фразы. В сторонние программы передаются только финальные фрагменты.
- **Быстрый запуск:** настраиваемое сочетание (по умолчанию `Ctrl + Alt + Space`) или кнопка записи. Приложение может работать из системного трея.
- **Собственная горячая клавиша:** запись нажатием клавиш или ручной ввод на вкладке «Параметры», проверка конфликтов Windows и сохранение между запусками.
- **Ввод в активное поле:** Windows UI Automation проверяет доступность редактирования, включая признак «только чтение»; вставка выполняется через Unicode `SendInput`, **без замены буфера обмена**. Если возможность редактирования подтвердить нельзя, текст остаётся в очереди.
- **Отложенная вставка:** если подходящее поле не выбрано, распознанный текст остаётся в оперативной памяти. При включённой опции наведение на поле примерно на 700 мс запускает однократную попытку ввода.
- **Защита от повторов:** учёт `session_id` / `segment_id`; после неоднозначного результата ввод автоматически не повторяется.
- **Правка по желанию:** кнопка «Открыть редактор» показывает накопленный текст. После остановки записи его можно исправить, скопировать или очистить. Следующая диктовка добавляется к сохранённому тексту.
- **Одна запись через любые паузы:** каждая завершённая фраза Vosk добавляется с новой строки в текущую запись и при автовставке. Перенос передаётся как текст, без нажатия Enter. Остановка и повторное включение микрофона также продолжают запись с новой строки.
- **Новая запись и очистка:** маленькая голубая кнопка справа начинает следующую запись без остановки микрофона; розово-сиреневая слева и «Очистить» в редакторе очищают текущую, в том числе во время диктовки. Предыдущие записи доступны во вкладке «Очередь».
- **Автоматическая новая запись:** необязательный режим с интервалом тишины 1–60 секунд, по умолчанию 3. После паузы следующая речь начинает новую запись; пустые записи во время тишины не создаются.

**Приложение никогда не нажимает Enter и не отправляет сообщения самостоятельно.**

## Требования

| Компонент | Требование |
| --- | --- |
| ОС | Windows 10/11, x64 |
| Распознавание | CPU; отдельная GPU не нужна |
| Микрофон | Любой работающий вход с разрешением доступа в Windows |
| Интерфейс | Microsoft Edge WebView2 Runtime |
| Сборка из исходников | Rust stable (MSVC, минимум 1.90), Visual Studio C++ Build Tools, PowerShell 7+ |
| Сеть | Требуется для загрузки сборки, зависимостей и ручной проверки обновлений; **для самой диктовки не нужна** |

Frontend — статические HTML, CSS и JavaScript. Node.js, npm и отдельная база данных не требуются.

## Быстрый старт из исходников

Откройте **PowerShell** на Windows:

```powershell
git clone https://github.com/Lotargo/voice-input.git
cd voice-input

# Загрузить Vosk для Windows и небольшую русскую модель
.\scripts\prepare-assets.ps1

# Установить CLI Tauri, если он ещё не установлен
cargo install tauri-cli --version '^2' --locked

cd src-tauri
cargo tauri dev
```

Скрипт `prepare-assets.ps1` получает нативную библиотеку **Vosk 0.3.45** и модель **vosk-model-small-ru-0.22** из официальных источников. Загрузка выполняется при подготовке, а не во время распознавания. Ресурсы хранятся локально в `src-tauri/resources/` и не коммитятся в Git.

Перед передачей пути к модели в Vosk приложение нормализует Windows-пути, в том числе канонические пути с префиксом `\\?\`, которые возвращает Tauri. После загрузки модели и запуска микрофона статус меняется на «Запись идёт».

### Как пользоваться

Вкладка **«Диктовка»** по умолчанию показывает компактный голосовой ввод. Редактор доступен через **«Открыть редактор»**; диктовка и автовставка работают при закрытом редакторе. Выбор модели вынесен в **«Модель»**. В **«Параметрах»** есть разделы **«Звук»**, **«Диктовка»** и **«Обновления»**; таймер тишины, вставка при наведении и горячая клавиша находятся в разделе «Диктовка». Ожидающие и неподтверждённые фрагменты и завершённые записи доступны в **«Очереди»**. Ожидающие фрагменты и счётчик объединены по записям.

1. Установите курсор в редактируемое поле (например, в чате или текстовом редакторе).
2. Нажмите **Ctrl + Alt + Space** или **«Начать диктовку»**.
3. Говорите. Промежуточный текст появится в окне Voice Input, подтверждённые фрагменты будут передаваться в поле ввода.
4. Повторно нажмите горячую клавишу для остановки. Проверьте текст и при необходимости исправьте его перед отправкой.

Если активного поля нет, текст попадёт в **ожидающую очередь**. Можно навести курсор на подходящее поле (если включена опция), либо нажать **«Копировать»** и вставить вручную.

Вкладки можно переключать стрелками влево/вправо; Home и End выбирают первую и последнюю вкладку. Переключение сохраняет текст и состояние записи. Скрытые полосы прокрутки не отключают прокрутку: используйте колесо мыши или клавиатуру после перехода к нужной области через Tab.

Кнопки заголовка сворачивают и разворачивают окно; крестик скрывает приложение в трей. Для полного выхода выберите **«Выход»** в меню трея.

> **Важно:** наведение автоматически переводит фокус на подходящее поле и может быть нежелательно во время другой работы. Опцию можно отключить в интерфейсе.

### Ручная правка текста

1. Остановите диктовку кнопкой или **Ctrl + Alt + Space**.
2. Нажмите **«Открыть редактор»**. Исправьте слова, добавьте пунктуацию или переносы строк в поле **«Распознанный текст»**.
3. Нажмите **«Копировать»** и вставьте исправленный вариант вручную. Если исходный текст уже находится в другом приложении, выделите его для замены исправленным вариантом.

При правке, копировании или очистке связанные ожидающие фрагменты снимаются с автовставки. Уже выполненные и неподтверждённые попытки не запускаются повторно. Изменения относятся к тексту в окне Voice Input; замена текста в стороннем редакторе выполняется вручную.

Во время записи поле доступно для чтения, а ручная правка и копирование доступны после остановки. Следующее включение микрофона дописывает текущую запись с новой строки и сохраняет внесённые исправления. **«Очистить»** в редакторе и боковая кнопка очистки работают и при включённом микрофоне: удаляют текущий текст, ожидающие фрагменты и незавершённую гипотезу. Текст, история и правки хранятся только в памяти приложения; системный буфер обмена меняется по явному нажатию **«Копировать»**.

Открытие и скрытие редактора сохраняет текст и состояние записи. Само открытие редактора не переводит ожидающие фрагменты на ручную вставку; этот переход выполняется при правке, копировании или очистке.

### Записи, паузы и таймер тишины

В обычном режиме паузы любой длины сохраняют одну запись. Центральная кнопка управляет микрофоном. Кнопка справа завершает текущую запись и открывает следующую, сохраняя непрерывный захват. Кнопка слева начинает текущую запись заново: удаляет её текст, ожидающие фрагменты и незавершённую гипотезу. Завершённые предыдущие записи остаются во вкладке **«Очередь»**, откуда их можно скопировать. Уже вставленный во внешнее поле текст удаляется пользователем вручную; кнопки не отправляют сообщения и не очищают сторонние поля.

Для автоматического разделения включите **«Параметры» → «Новая запись после тишины»**. Значение **«Интервал тишины»** — целое число от **1 до 60 секунд**, по умолчанию **3**. Режим по умолчанию выключен, выбор сохраняется между запусками. Прежняя настройка остановки по окончании фразы Vosk больше не используется.

Локальный [Earshot VAD](https://docs.rs/earshot/1.2.2/earshot/) определяет речь в том же PCM 16 кГц, который получает Vosk, после выбранной обработки звука. Отсчёт идёт от конца последних речевых кадров, независимо от начала диктовки и внутренних границ фраз Vosk. Начальная тишина не запускает таймер, а непрерывная речь продлевает текущую запись. После истечения интервала завершается хвост предыдущей фразы; следующая запись открывается при возобновлении речи. Микрофон остаётся включённым. Шум и очень тихая речь могут влиять на определение границы.

### Микрофон и шумоподавление

Откройте **«Параметры → Звук»** или нажмите название микрофона внизу окна. Выберите **«По умолчанию в Windows»** либо конкретное устройство. Список обновляется кнопкой рядом. Для смены микрофона и шумоподавления сначала остановите диктовку и проверку уровня.

Конкретный микрофон запоминается по идентификатору устройства. Если он отключён или недоступен, приложение покажет сообщение и не подменит его другим. При потере устройства во время диктовки захват останавливается, уже распознанный текст остаётся в текущей записи. Подключите устройство снова или явно выберите другое. После переустановки драйвера идентификатор может измениться — тогда выберите микрофон повторно.

**«Проверить микрофон»** показывает исходный уровень и уровень после обработки, подсказки о тишине, высоком уровне и перегрузке. Проверка длится до 20 секунд и прекращается кнопкой, при уходе из раздела «Звук», скрытии окна или потере фокуса. Она не запускает Vosk, не меняет транскрипцию и очередь и не сохраняет аудио. Можно сравнить уровни с выключенным и включённым шумоподавлением в двух последовательных проверках.

**«Шумоподавление»** по умолчанию выключено. При включении сигнал проходит фильтр низкого гула с частотой среза 100 Гц и RNNoise через библиотеку nnnoiseless на 48 кГц, затем преобразуется в 16 кГц для распознавания. Обработка локальная, на CPU. Это вариант для постоянного шума вентилятора и гула; результат зависит от микрофона и окружения. Исходные пики измеряются до фильтров: цифровая перегрузка остаётся видимой, даже если обработанный сигнал стал тише.

Выбор устройства и шумоподавления хранится в `%APPDATA%\dev.lotargo.voiceinput\audio.json`; настройка общая для installed- и portable-копии этого пользователя.

### Реакция волны на звук

Громкость рассчитывается по RMS и пикам сигнала, частотный состав по восьми полосам 60–8000 Гц. Rust анализирует окна по 1024 отсчёта обработанного PCM 16 кГц, примерно 15 раз в секунду, с окном Ханна и [RustFFT](https://docs.rs/rustfft/6.4.1/rustfft/). В интерфейс передаются только уровни и доли энергии; отдельный доступ к микрофону из WebView не нужен.

В ожидании и при тишине волна сохраняет мягкое движение примерно с 10 обновлениями в секунду. Во время речи растут размах, скорость и яркость, а соотношение частот меняет рисунок. Сглаженная активная перерисовка ограничена примерно 30 кадрами в секунду; на других вкладках и в скрытом окне движение полностью приостанавливается. При уменьшенном движении в Windows непрерывная анимация отключается, но форма и цвет продолжают реагировать на звук. При пропадании данных и остановке записи волна возвращается к состоянию покоя.

Для индикации уровня Rust дополнительно передаёт абсолютный цифровой пик и долю исходных отсчётов около границы диапазона (модуль от 0,985), до шумоподавления и ресемплинга. Янтарное предупреждение возникает при устойчивом RMS от 0,2 либо пике от 0,8; коралловое — при RMS от 0,42, пике от 0,985 или доле таких отсчётов от 0,5%. Обычные пики проверяются примерно 140 мс, значительная доля отсчётов у границы включает предупреждение сразу. Удержание и задержка возврата уменьшают мерцание. Это оценка цифрового сигнала и запаса до перегрузки, а не измерение акустической громкости в комнате. Сама визуализация не изменяет звук.

### Своя горячая клавиша

Откройте **«Параметры → Диктовка → Горячая клавиша»**. Нажмите **«Записать»**, затем нужное сочетание и **«Применить»**. При русской раскладке учитываются физические клавиши, например клавиша `К` записывается как `R`. Можно ввести сочетание вручную, например `Ctrl+Shift+F9`. Используйте Ctrl, Alt или Win вместе с одной клавишей; F1–F24 доступны и отдельно. Esc отменяет запись сочетания; нажатие текущего сочетания в этом режиме не включает диктовку. Уход на другую вкладку, потеря фокуса и 15 секунд ожидания также отменяют захват.

**«По умолчанию»** возвращает `Ctrl+Alt+Space`. Изменение действует сразу, в том числе при скрытом окне. Если сочетание занято или зарезервировано Windows, прежняя работающая настройка сохраняется. Если конфликт обнаружен при запуске, окно остаётся доступным: выберите другую комбинацию или используйте кнопку записи.

Сочетание хранится в `hotkey.json` в каталоге конфигурации приложения (`%APPDATA%\dev.lotargo.voiceinput\`); настройка общая для установленной и portable-копии этого пользователя. Запускайте одну копию одновременно, чтобы они не конкурировали за глобальные сочетания.

### Смена модели

На вкладке **«Модель»** видны установленные и доступные для загрузки модели. **Vosk Small RU** входит в пакет приложения. Две дополнительные модели в установщик и portable-архив не включаются:

| Модель | Файлы | Работа |
| --- | --- | --- |
| GigaAM v3 E2E | 231 898 272 байта, около 231,9 МБ | Русский текст с пунктуацией и регистром после завершения фразы |
| Nemotron 3.5 ASR | 682 215 356 байт, около 682,2 МБ | Потоковая русская диктовка с пунктуацией и предварительным текстом |

**«Загрузить»** начинает скачивание только по вашему действию. **«Пауза»** сохраняет полученные байты; **«Продолжить»** использует сохранённую часть. Разрыв соединения и экстренное закрытие приложения также сохраняют незавершённую загрузку. После запуска нажмите «Продолжить»: автоматического выхода в сеть нет. **«Отменить»** удаляет только незавершённую загрузку этой модели. Если сервер временно недоступен или не подтвердил HTTP-диапазон, сохранённая часть не перезаписывается. Каждый готовый файл проверяется по SHA-256, модель появляется среди установленных только после завершения всех проверок.

После получения всех файлов карточка переходит в **«Проверка файлов»**: отдельно показывает объём, проверенный по SHA-256. Пока проверка не завершена, назначить модель основной нельзя. Проверку можно приостановить; после закрытия приложения кнопка **«Проверить»** завершает её по сохранённым файлам без повторного скачивания. Открытая вкладка сверяет статус с локальным загрузчиком каждую секунду, без обращения к сети.

**«Сделать основной»** сохраняет выбор между запусками, в том числе для горячей клавиши при скрытом окне. Для удаления основной модели сначала выберите другую. Смена и удаление моделей блокируются во время записи и установки обновления. Чтобы установить обновление приложения, сначала поставьте загрузку модели на паузу.

Модели и незавершённые загрузки хранятся в `%LOCALAPPDATA%\dev.lotargo.voiceinput\models\`, выбор основной модели - в `%APPDATA%\dev.lotargo.voiceinput\models.json`. Эти пути закреплены за профилем пользователя Windows и не зависят от папки EXE или формата поставки. Установленная и portable-копия используют одни данные; переносить веса рядом с portable не нужно. Второй экземпляр приложения открывает окно уже работающего.

Если при удалении установленной версии выбрать сохранение данных, следующая установленная или portable-копия обнаружит проверенные модели и незавершённые загрузки в том же каталоге. Пауза сохранится до явного продолжения. Выбор модели сохраняется по её идентификатору в каталоге: встроенный Vosk разрешается в папку запущенной копии, скачанная модель — в общий каталог AppData. Старые настройки поддерживаются. Это переносимость между копиями на одном компьютере и под тем же пользователем Windows; при переносе portable на другой компьютер модели нужно загрузить там.

Выбрать можно только встроенный Vosk Small RU и установленные модели из каталога. Произвольные папки не поддерживаются. Если ранее была выбрана своя модель, приложение попросит явно выбрать поддерживаемую; её файлы не удаляются. Если основная модель пропала, она не подменяется автоматически.

При обычной интерактивной деинсталляции появится вопрос: сохранить скачанные модели, незавершённые загрузки и настройки или удалить их. Удаление данных затрагивает общий профиль всех копий, включая portable. Обновление и тихое удаление сохраняют данные.

Модели скачиваются напрямую из закреплённых версий файлов их авторов на Hugging Face. Каталог встроен в приложение; при запуске он не запрашивает список моделей из сети. Диктовка остаётся полностью локальной. Для GigaAM/Nemotron используется нативный CPU runtime sherpa-onnx; Python не требуется. Телеметрия ONNX Runtime отключается до загрузки моделей.

Дополнительные модели уже используют INT8: у GigaAM квантован основной кодировщик, у Nemotron также декодировщик и joiner. Небольшие декодировщик и joiner GigaAM остаются в исходном формате экспорта. Полные FP16/FP32-веса этих моделей не скачиваются. CPU-профиль использует от 1 до 4 потоков с учётом доступных логических ядер, отключает активное ожидание рабочих потоков ONNX Runtime и оставляет включёнными оптимизации графа. Размеры и контрольные суммы весов не меняются; повторная загрузка не нужна. Замеры и их границы приведены в [отчёте производительности](../docs/qa/recognition-performance-2026-11-15.md).

## Сборки и обновления

Скачайте подходящий вариант из [последнего релиза](https://github.com/Lotargo/voice-input/releases/latest):

| Вариант | Ссылка | Запуск |
| --- | --- | --- |
| Portable | [ZIP Windows x64](https://github.com/Lotargo/voice-input/releases/latest/download/Voice-Input-Portable-windows-x64.zip) | Распакуйте `Voice-Input` целиком, запустите `voice-input.exe` |
| Установка | [Установщик Windows x64](https://github.com/Lotargo/voice-input/releases/latest/download/Voice-Input-Setup-windows-x64.exe) | Запустите установщик, затем ярлык Voice Input |

Portable требует установленный WebView2. Не переносите EXE отдельно от DLL, `models/` и `portable.json`.

В **«Параметры → Обновления»** показаны версия и тип сборки. **«Проверить обновления»** обращается к публичному GitHub Releases без токена. Автоматической проверки при запуске нет. Если доступна новая версия, появляется отдельная кнопка **«Обновить и перезапустить»** с описанием изменений. Завершите диктовку и скопируйте нужный текст редактора и очереди: при перезапуске записи из памяти теряются.

Установленная версия запускает подписанный пакет NSIS и перезапускается после установки. Portable проверяет подписанный ZIP, распаковывает его до закрытия приложения, заменяет файлы **в той же папке** и запускается оттуда же. Посторонние файлы не удаляются. При ошибке замены выполняется откат из резервной копии. Папка portable должна быть доступна для записи. Служебные файлы и резервные копии находятся в `%LOCALAPPDATA%\dev.lotargo.voiceinput\updates\`; результата обновления нет в диктовке, он отображается в настройках.

**С версии 0.1 перейдите на 0.2 вручную один раз:** в старых сборках обновляющего механизма ещё нет. Последующие обновления доступны в приложении. Релизные пакеты имеют подпись обновления, привязанную к версии. Это не Authenticode-сертификат Windows; SmartScreen может показывать предупреждение.

## Локальная сборка для Windows

CI отсутствует; сборка и публикация выполняются вручную. Единственный источник версии — `src-tauri/Cargo.toml`, формат `MAJOR.MINOR.PATCH`, тег `vX.Y.Z`.

Для разработки без приватного ключа релизов:

```powershell
cd src-tauri
cargo tauri dev
# NSIS без генерации подписанных пакетов обновления:
cargo tauri build --bundles nsis --config '{"bundle":{"createUpdaterArtifacts":false}}'
```

Подписанная сборка владельца:

```powershell
.\scripts\build-windows.ps1 -SkipPrepare
```

Скрипт берёт существующий ключ подписи вне репозитория, собирает NSIS, проверяет встроенные иконки и Vosk в portable-папке, подписывает архив и создаёт метаданные:

```text
dist/
  portable/0.3.1/
    Voice-Input/                         # распакованная программа
    Voice-Input-Portable-windows-x64.zip
    Voice-Input-Portable-windows-x64.zip.sig
  installers/0.3.1/
    Voice-Input-Setup-windows-x64.exe
    Voice-Input-Setup-windows-x64.exe.sig
  releases/0.3.1/
    latest.json                          # установленная версия
    latest-portable.json                 # portable
    SHA256SUMS.txt
    build.json                           # локальная связь с коммитом
  archive/                               # прежние промежуточные сборки
```

Без `-SkipPrepare` скрипт также подготавливает DLL и модель. `-OutputDirectory` задаёт другой корневой каталог с той же структурой. Установщик Tauri дополнительно остаётся в `src-tauri/target/release/bundle/nsis/`. Порядок следующего релиза, подписи и публикация описаны в [releases/README.md](../releases/README.md).

## Архитектура

```text
Microphone (CPAL)
  └─ PCM → mono → optional 48 kHz high-pass + RNNoise → 16 kHz
      └─ Vosk (локальная модель)
          ├─ partial → окно приложения
          └─ final → Delivery Queue (RAM, deduplication)
                        ├─ активное поле → UI Automation → SendInput
                        └─ нет поля → ожидание / ручное копирование
```

| Путь | Назначение |
| --- | --- |
| `src-tauri/src/audio.rs` | Захват микрофона, потоковая сессия, остановка при потере устройства |
| `src-tauri/src/audio/settings.rs` | Список устройств, устойчивые идентификаторы и сохранение выбора |
| `src-tauri/src/audio/processing.rs` | Ресемплинг с фильтром от наложения спектров, RNNoise, исходные уровни |
| `src-tauri/src/audio/visualizer.rs` | RMS, пики и спектральные полосы для волны |
| `src-tauri/src/audio/pipeline.rs` | VAD, распознавание и переключение без перезапуска микрофона |
| `src-tauri/src/audio/silence.rs` | Таймер от конца речи, настройки 1–60 секунд |
| `src-tauri/src/records.rs` | Текущая запись, поколения очистки, история и ручные правки |
| `src-tauri/src/vosk.rs` | Загрузка `libvosk.dll` и вызовы нативного Vosk |
| `src-tauri/src/delivery.rs` | UI Automation, очередь, дедупликация, ввод текста |
| `src-tauri/src/models.rs` | Обнаружение локальных моделей и DLL |
| `src-tauri/src/lib.rs` | Tauri-команды, трей, горячая клавиша, состояние |
| `src-tauri/src/hotkey.rs` | Проверка, регистрация и сохранение глобального сочетания |
| `src-tauri/src/updates.rs` | Проверка GitHub Releases, загрузка и подпись, NSIS |
| `src-tauri/src/updates/portable.rs` | Подписанный ZIP, замена файлов portable и откат |
| `ui/` | Локальный интерфейс без frontend-сборщика |
| `ui/wave.js` | Визуализация уровней с ограничением частоты кадров |
| `ui/records.js` | Представление записей с защитой от устаревших событий и ответов |

Настройки интерфейса сохраняются через WebView localStorage, горячая клавиша и звук — в отдельных локальных JSON-файлах; **транскрипции и очередь в базу данных не записываются**. После выхода из приложения ожидающий текст теряется.

## Ограничения

- Ввод реализован как **best-effort**. `SendInput` подтверждает передачу событий Windows, но не факт появления текста в стороннем приложении. Гарантируется максимум **одна автоматическая попытка** на фрагмент, а не exactly-once запись в редактор.
- UI Automation работает не со всеми кастомными полями (включая отдельные редакторы Electron/IDE). Поле должно предоставлять `ValuePattern` с отключённым `IsReadOnly` либо `TextPattern` с явно доступным для записи текстом. Парольные поля и элементы с неподтверждённой доступностью редактирования пропускаются. В таких случаях используйте ручное копирование. См. [ValuePattern](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nn-uiautomationclient-iuiautomationvaluepattern) и [IsReadOnly для TextPattern](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.textpattern.isreadonlyattribute).
- Приложения, запущенные с повышенными правами, могут отклонять ввод из обычного процесса.
- При автовставке перенос передаётся символом LF, без Enter или CR. Некоторые поля его отбрасывают: это воспроизведено в браузерных полях Edge при проверке символьного ввода. В журнале и при ручном копировании переносы сохраняются; клавиша Enter для обхода ограничения не используется.
- Автоматическое разделение использует VAD; на точность границ влияют шум и уровень микрофона. Это разделение локальных записей, а не автоматическая отправка сообщений.
- В версии 0.3 отсутствуют **wake word**, LLM/API-провайдеры и непосредственное изменение файлов Excel. Это диктовка текста в поле ввода, а не агент, управляющий документами.

## Проверка и участие

На Windows в каталоге `src-tauri/`:

```powershell
cargo fmt
cargo test --locked
```

Перед проверками подготовьте DLL и модель скриптом `scripts/prepare-assets.ps1`. Помимо модульных тестов, `cargo test` проверяет реальный Vosk на тишине и доступность записи в скрытых нативных Windows-полях. Для горячей клавиши проверяются конфликты и ошибки сохранения с подменой регистратора, отсечение старых событий, захват без включения записи и чтение/замена реального JSON-файла на Windows. Эти проверки не нажимают клавиши в сторонних приложениях, не используют микрофон и не меняют буфер обмена.

Проверки событий интерфейса можно запустить из корня репозитория, если установлен Node.js с поддержкой `node:test`:

```powershell
node --test scripts/test-ui.cjs
```

Они проверяют повторные сессии, новую запись и очистку при включённом микрофоне, защиту от запоздавшего текста, историю, настройки таймера, ручную правку, копирование, очередь и вкладки. Визуальные проверки покрывают компактный ввод, громкость и частоты, уменьшенное движение и паузу скрытой анимации. Rust-тесты дополнительно пропускают синтетическую русскую речь с короткими и длинными паузами через реальные Vosk и VAD; проверяют тишину до первой речи, границы 1 и 60 секунд, сброс гипотезы и сохранение PCM. Файл речи создан локальным синтезатором Windows и не содержит записи с микрофона. Для работы приложения и Windows-сборки Node.js не требуется. `src-tauri/Cargo.lock` фиксирует версии Rust-зависимостей; сгенерированные схемы `src-tauri/gen/` в Git не включаются.

Для обновлений проверяются отсутствие сетевого вызова при старте UI, отдельное подтверждение установки, блокировка во время диктовки и повторного нажатия, ошибки/прогресс, отказ при подмене подписанных байтов или версии, недопустимые ZIP-пути и откат файлов. Владельцу ключа доступен `scripts/test-portable-update.ps1 -HelperExecutable <путь-к-EXE>`: в изолированных папках он проверяет реальный помощник на обновлении, повреждённом пакете и заблокированной DLL. Тестовые процессы не используют микрофон, буфер обмена и пользовательскую установку.

Полный путь обновления через NSIS проверен в отдельной установленной копии: приложение загрузило настоящий релиз 0.2.0, установщик заменил файлы и автоматически запустил новую версию в той же папке. Подробности, контрольные суммы и границы проверки — в [отчёте NSIS](../docs/qa/nsis-update-2026-11-14.md).

Для звука проверяются сохранение устройства, отсутствие неявной подмены отключённого входа, завершение потока при ошибке с сохранением принятых кадров, подавление наложения спектров, видимость исходной перегрузки и синтетическая русская речь с шумом через настоящий Vosk. UI-тесты проверяют выбор и откат настроек, изоляцию проверки уровня от транскрипции и очереди, её остановку при уходе и гонку запуска с закрытием раздела. Результаты и границы проверки 0.3.0 — в [отчёте звука](../docs/qa/audio-input-0.3.0-2026-11-14.md).

Для каталога проверяются продолжение HTTP Range после обрыва, пауза, отмена, контрольные суммы, отдельный этап проверки и восстановление пропущенного события завершения. Результаты загрузок и распознавания двух настоящих моделей, включая обнаруженные ошибки в числах, приведены в [отчёте 0.4.0](../docs/qa/model-catalog-0.4.0-2026-11-15.md).

Подготовка релиза 0.4.1 и исправление поиска CPU-профиля при обычном запуске GigaAM/Nemotron описаны в [отчёте выпуска](../docs/qa/release-0.4.1-2026-11-15.md).

Перед использованием в работе проверьте Notepad, поля ввода Chrome/Edge, OpenCode, VS Code и Excel (в частности, строку формул), смену фокуса, парольные поля, отложенную вставку и отсутствие повторов. Историю изменений и предложения по доработкам можно вести через [Issues](https://github.com/Lotargo/voice-input/issues).

При работе с кодом учитывайте [AGENTS.md](../AGENTS.md).
