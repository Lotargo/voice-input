# CLI и локальное управление

`voice-input-cli.exe` поставляется рядом с `voice-input.exe` в portable и NSIS. Он управляет уже запущенным приложением текущего Windows-профиля. Сначала запустите Voice Input обычным способом. CLI сам приложение не запускает и микрофон без команды не включает.

```powershell
.\voice-input-cli.exe --help
.\voice-input-cli.exe status
.\voice-input-cli.exe models
.\voice-input-cli.exe select-model gigaam-v3-e2e
.\voice-input-cli.exe start
.\voice-input-cli.exe stop
.\voice-input-cli.exe quit
```

| Команда | Результат |
| --- | --- |
| `status` | PID, версия, состояние записи/проверки, очередь доставки |
| `models` | Каталог, доступность, ID и основная модель |
| `select-model ID` | Явный выбор установленной модели из каталога; ID берите из `models` |
| `start` | Запуск обычной диктовки с существующими настройками и правилами доставки |
| `stop` | Остановка диктовки/проверки; ответ только после завершения рабочего потока и уничтожения модели |
| `mic-test` | Обычная проверка уровня микрофона до 20 секунд, без модели, текста и доставки |
| `records` | Снимок текущей записи и истории из RAM; чтение не забирает очередь |
| `new-record` | Следующая логическая запись; действуют общие правила FIFO и проверки поколения |
| `clear-record` | Очистка текущей записи и её ожидающих фрагментов; внешний текст пользователь удаляет сам |
| `show`, `hide` | Показать/скрыть окно; скрытие останавливает проверку микрофона, обычная диктовка продолжается |
| `quit` | Дождаться освобождения модели, подтвердить запрос и выйти; во время установки обновления команда отклоняется |

`start` и `mic-test` подтверждают принятие команды. Загрузка модели и открытие устройства происходят асинхронно: проверяйте `status.result.recording`. `recording=true` и непустое `input_name` означают запущенный захват; при ошибке запуска `recording=false`, а `message` содержит причину. Завершённый `stop` возвращает `model_released=true`.

Каждый вызов выводит одну JSON-строку в stdout: `{"ok":true,"result":...}` или `{"ok":false,"error":"..."}`. `--help` и `--version` выводят обычный текст. Код завершения: 0 - успех, 1 - ошибка команды/соединения, 2 - лишние позиционные аргументы. При отсутствии сервера команда завершается с ошибкой.

Вызовы не повторяются автоматически. Таймаут ответа составляет 120 секунд. Разрыв или таймаут не доказывает, что команда не выполнилась: проверьте состояние перед дальнейшими действиями, особенно перед `new-record` или `clear-record`. Ошибка занятости pipe также возвращается вызывающему приложению.

## Прямой IPC

Транспорт: локальный Windows named pipe `\\.\pipe\dev.lotargo.voiceinput-<hash>`, где `<hash>` - SHA-256 от UTF-8 строки `%APPDATA%` после перевода в нижний регистр (hex). Используется стандартный Windows DACL процесса; удалённые клиенты отклоняются. Это локальный интерфейс доверенных приложений профиля, без HTTP, TCP-порта, токена или облака. Не запускайте Voice Input с повышенными правами для обычной автоматизации.

Один запрос и один ответ на соединение. Запрос - JSON в UTF-8 с завершающим LF, максимум 16 КиБ вместе с LF, время чтения 2 секунды. Поля: `command` (строка) и необязательное `argument` (строка, только для `select-model`). Неизвестные поля отклоняются. Пример:

```json
{"command":"select-model","argument":"nemotron-3-5-ru"}
```

Запросы обслуживаются последовательно. Не держите пустые соединения. Для интеграции предпочтителен запуск CLI с захватом stdout и кода завершения.

## Память и закрытие

Модель загружается на время диктовки. Остановка захвата завершает принятые аудиоблоки и распознавание, закрывает decoder worker, уничтожает распознаватель и модель. Нативный runtime ONNX сохраняет небольшой общий объект окружения до завершения процесса; это не хранение весов модели. Windows и аллокаторы могут сохранять часть выделенных страниц, поэтому размер процесса после остановки не обязан совпадать с исходным байт в байт.

Крестик скрывает окно в трей и сохраняет обычную диктовку. Это не выход. Для завершения используйте «Выход» в трее или `quit`. Настоящий выход блокирует новые сеансы и дожидается рабочего потока. Нативная загрузка/инференс не прерываются принудительно посередине вызова: выход может ждать их завершения. Принудительное завершение процесса Windows освобождает его память средствами ОС, без гарантии завершения текущего текста.

Проверка памяти и ограничения: [отчёт](qa/model-lifecycle-cli-2026-11-15.md).

## Совместимость portable-обновления

Старые portable-сборки с прежним списком разрешённых файлов обновления отклонят архив, содержащий новый `voice-input-cli.exe`. Для первого перехода на пакет с CLI распакуйте новый portable-пакет вручную. В текущем исходном коде CLI уже включён в список разрешённых файлов и общий механизм резервирования/отката. NSIS включает утилиту как дополнительный бинарный файл. Для portable 0.4.2 и старше первый переход на 0.4.3 требует ручной распаковки нового ZIP после выхода из приложения. Модели и настройки в AppData сохраняются.
